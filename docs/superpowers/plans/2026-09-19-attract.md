# Attract Subsystem and State Tails (4d) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the boot/attract sub-machine `0x11000` and the front-end state tails so the port boots through state 0 (attract) as the original does, produces the title's credit row itself, and renders the attract scene through the real scroll/zoom projection.

**Architecture:** A new `port/src/game/attract.{c,h}` owns the `0x11000` 13-phase machine, the per-state tails (`0x10DB0`/`0x10E18`), the reset/scheduler (`0x10EE4`/`0x10F28`) and the per-bit scene tick (`0x292AC`). `port/src/platform/render.c` gains the scroll/zoom projection (`0x389C4`/`0x38A38`) because it writes compositor projection state. `flow.c` keeps only the state dispatch. Proof is a continuous headless run aligned to the existing post-logo captures (attract prefix + title window), an env-gated `PR_ATTRACT_DUMP` driver, and raw-derived unit tests.

**Tech Stack:** C11 (fixed port profile), the existing `make verify` ladder, capstone for raw derivations, SDL3 only in `host.c`/`main.c`.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-09-19-attract-design.md`. Base is `main` at `6a7abd2`.
- `data/` is read-only; `tools/` must not be modified (new tools are added, existing ones untouched).
- No new dependencies. Build 0 warnings. Stage explicit paths only; never `git add -A`. Commit style `<area>: <what changed>`.
- `mem[]` holds original state at original offsets; never write `mem[0xA0000]`. SDL only in `port/src/host.c`/`port/src/main.c`.
- Comments in `port/src` only `/* PORT: ... */`, `/* TODO(verify): ... */`, and address tags.
- Tests: only `CHECK(cond,msg)` / `CHECK_EQ_INT(a,b)` (NO message arg on CHECK_EQ_INT); declared in `port/tests/test.h`, called from `port/tests/run_tests.c`.
- `port/src/symbols.h` must regenerate byte-identically: `python3 tools/gen_symbols.py port/decomp port/src/symbols.h`.
- **Register-level fidelity, no fitted constants.** Every value comes from the raw bytes of `data/game/C/PRAGE.EXE` or an existing port constant. `file_offset = va + 0x52E54` for obj-0, `va + 0x46E54` for obj-1. Where the decompiler and the raw disagree, the raw wins.
- **Address bases.** Raw displacements below an object's mapped base are link-time offsets: obj-0 (+`0x10000`), obj-1 (+`0x80000`). Data refs below `0x80000` therefore fix to `+0x80000` (e.g. `0x1AC08`→`0x9AC08`, `0x70A6F`→`DS_000F0A6F`). Determine each immediate's base from its fixup; do not assume.
- `game_init()` may be called **once per process**. Any test that calls it must run alone, env-gated, exactly as `test_title()` does.
- **Voice `0x2C3FC` stays a declared no-op stub.** States 3/4 (`0x12484`/`0x11578`), the fight states 5–9, the `0x13xxx` effect render path, and the EEPROM storage stay stubs.
- **`tools/` existing files are read-only.** New comparison tooling is a new file.

### Task 4: `attract_step` — the `0x11000` machine, and the boot integration

The 13-phase machine. **This task is derivation-driven**: the decompiler drops several
register arguments, so Step 1 recovers them from the raw before any code is written, and
the code block carries `STEP1_*` markers for exactly those sites. **No `STEP1_` marker may
remain in the committed code.** This is the repository's established pattern for
decompiler-unreliable functions (4b-A's `0x2D6F8`, 4b-B's `0x11F6C`).

**Verified phase table** (`cs:[eax*4 + 0xFCC]`, fixed to linear `0x10FCC`):

| phase | address | phase | address |
|---|---|---|---|
| 0 | `0x1101F` | 7 | `0x1128C` |
| 1 | `0x1106B` | 8 | `0x112CA` |
| 2 | `0x11089` | 9 | `0x112FD` |
| 3 | `0x11199` | 0xA | `0x11478` |
| 4 | `0x111C6` | 0xB | `0x114BC` |
| 5 | `0x1121C` | 0xC | `0x11531` |
| 6 | `0x11254` | default (`>0xC`) | tail at `0x11550` |
